This report's one real failure mode is crying wolf: v1/v2c reads are extremely common and are NOT by themselves evidence of an unhardened device -- HP's "Secure by Default" (FutureSmart 4.5+) disables SNMPv1/v2 writes while leaving reads answering, and a technician sent to "fix" such a printer finds nothing to fix and stops believing the next report. So the page states its own scope: it grades the monitoring path we configured, which we can prove, and declines to guess at the device's own write policy, which we never test. #}

What this asserts: the SNMP transport this system uses to poll each device (from the subnet's version and USM security level), and whether that subnet's community string is still a vendor default. Both are facts about our own configuration.

What it does not assert: that a device accepts SNMP writes. SET is the attack that reconfigures a printer, we never attempt one, and current firmware commonly refuses writes while still answering reads. Cleartext polling is an exposure of the monitoring path, not proof that a printer is unhardened.

Firmware is a visibility column, not a finding: “unknown” means the device exposed nothing parseable over SNMP, never that it is up to date.
