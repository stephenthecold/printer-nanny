How an occurrence-rate rule behaves

  • The window rolls: the count is always “since now minus the window”, so occurrences age out on their own.
  • It clears with a margin, not on the first dip — currently {{ clear_margin_pct | round | int }}% below the count (Settings → Alerts). Resolving the instant one occurrence ages out is how flapping starts.
  • While the alert is open its detail is rewritten each cycle with the current count, so it never sits there claiming a number the printer left behind hours ago.
  • The flap cooldown ({{ flap_cooldown_min }}m) folds a quick re-fire back into one incident — but for these rules it is capped at the rule's own window, because two firings that share no counted event are not the same incident.
