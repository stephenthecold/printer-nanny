{# "Data as of ..." -- the freshness strip. Rendered by base.html on every fleet-state surface, and re-rendered on its own by GET /fragments/freshness so an open tab keeps telling the truth. Both paths render THIS file, so the polled version can never drift from the initial one. WHAT IT SAYS, AND WHY IT SAYS IT THAT WAY ----------------------------------------- Every value here comes from central.freshness, which measures the age of the DATA (printers.last_seen / agents.last_heartbeat / the worker's success stamps). Nothing on this strip is derived from the time of the render -- a page built this second over four-hour-old readings says four hours. The absolute instant is authoritative and the relative age is a convenience, so both are shown: the absolute one cannot rot, and static/dashboard.js re-derives the relative one from the every few seconds. If polling stops -- tab backgrounded, network gone, server down -- the age keeps climbing instead of freezing on a comforting number. ACCESSIBILITY: THIS IS DELIBERATELY NOT A LIVE REGION ---------------------------------------------------- It re-renders on a timer, and a timer-driven aria-live region is a screen reader reading "data as of ... four hours ago" out loud every minute forever. The transition is the only part worth announcing, so it is announced once, from a separate stable live region in base.html that dashboard.js writes to only when data-pn-state actually changes. The strip itself carries the detail as ordinary text, reachable on demand like any other content. Composing with the stalled-worker banner above: that banner owns worker health and names the wedged jobs; this strip owns data age and never repeats it. The single exception is `warn_worker`, which central.freshness sets only for client_readonly viewers -- they are never shown the banner, and a stalled worker makes their portal lie exactly as much as it makes ours. #} {% from "_components.html" import btn, note %}
